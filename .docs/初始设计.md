## 一、设计目的

建立一个**可公网访问的自托管知识库文档站**，具备与语雀等商业文档平台对等的核心体验：

- **读**：公开发布的文档，访问者**无需任何鉴权**即可阅读；
- **写**：文档的增删改查**全部在 Web 前端完成**，不需要客户端软件；
- **控**：每篇文档可**单独控制是否发布**，未发布的保持私有；
- **管**：编辑与管理功能**必须登录**才能访问。

来源需求原文（2026-09-18）：

> 我需要的前端需要具有和语雀一样的前端 md 文档增删查改功能，并可以管理是否发布访问，
> 所有这些都只在 web 前端完成，访问公开发布的文档不需要访问者鉴权，但编辑管理功能需要登录才能访问。

后续追加的二次开发需求原文：

> Docmost 项目符合我的需求，但我需要进行一些前端的二次开发，例如中文化、外观改造、https 证书自签等功能。

### 为什么不直接使用 Obsidian

项目最初的方向是"为本地 Obsidian vault 部署一个 Web 前端"。经调研（见《设计审核》第六节）确认：
**Obsidian 生态不存在同时满足"Web 端增删改查 + 单篇发布开关 + 公开免鉴权读 + 编辑需登录"的产品**——
官方 Publish 只读且付费，社区插件（Quartz、Digital Garden、Perlite、Webpage HTML Export）全部是只读渲染器。
因此转向自托管 wiki 系统，Obsidian 仅作为本地 Markdown 编辑器保留（用于内容生产与备份）。

## 二、项目定位

**NyaaDoc = 基于 Docmost 的二次开发发行版。**

| 层 | 内容 | 归属 |
|---|---|---|
| 上游基座 | Docmost 开源版（AGPL-3.0），提供 Web 编辑器、页面树、权限、公开分享、Postgres 存储 | 上游维护 |
| 品牌层 | 中文文案补全、Logo/Favicon、产品名、主题外观 | **本项目** |
| 发行层 | Docker 镜像构建、compose 编排、部署脚本、nginx 接入、文档 | **本项目** |

本项目**不重新发明知识库内核**，只在上游之上做品牌化与部署工程；只有在品牌层无法覆盖时才进入源码级改造（V2）。

## 三、需求清单与验收口径

| 编号 | 需求 | 验收口径 |
|---|---|---|
| F1 | Web 端 Markdown 文档增删改查 | 浏览器内可创建页面、编辑正文、移动、删除、查看历史版本 |
| F2 | 单篇发布开关 | 每页有独立的"分享到网页"开关，可单独开关，可含/不含子页面 |
| F3 | 公开文档免鉴权 | 无痕浏览器打开公开链接可直接阅读，不跳转登录页 |
| F4 | 编辑管理需登录 | 未登录状态访问编辑入口/私有页面被拦截到登录页 |
| F5 | 中文化 | 界面主体为简体中文；上游已提供 `zh-CN` 语言包，本项目负责补漏与润色 |
| F6 | 外观改造（品牌化） | 产品名、Logo、Favicon、主题色呈现 NyaaDoc 品牌，不残留 Docmost 标识 |
| F7 | HTTPS 接入 | 通过自有域名 + TLS 访问；优先复用现有 Let's Encrypt 证书，必要时自签 |
| F8 | 可导出为 Markdown | 单页导出 `.md`；整个 Space 导出为保留层级的 Markdown ZIP |

## 四、技术栈与仓库形态

### 4.1 上游基座

| 项 | 取值 | 依据 |
|---|---|---|
| 上游项目 | `docmost/docmost` | 需求匹配度最高的开源方案 |
| 锁定版本 | **v0.96.0**（2026-09-08） | 上游最新 release = 镜像 tag `0.96.0` |
| 镜像 digest | `sha256:b56947fcfd08aab8fae12a377e1792784786adbf8b96e4281f14ef4fc072685a` | 不可变引用，避免 `latest` 漂移 |
| 运行依赖 | `postgres:18` + `redis:8` | 上游官方 compose |
| 镜像体积 | 209.3 MB | Docker Hub 实测 |

### 4.2 仓库形态

| 用途 | 位置 |
|---|---|
| 本地开发目录 | `H:\GitHub\NyaaDoc` |
| 品牌/发行仓库 | `https://github.com/NyaaCaster/NyaaDoc.git`（主分支 `main`，公有） |
| 上游源码（V2 才需要） | GitHub fork（fork 名固定为 `docmost`，**GitHub 不允许重命名 fork**） |

> **重要约束**：GitHub 的 fork 无法改名（社区讨论 #191091 已确认），
> 因此"fork 后改名 NyaaDoc"不可行。正确形态是**代码血缘与品牌发行分离**：
> fork 保留上游血缘用于 V2 源码改造，`NyaaDoc` 仓库承载品牌资产与部署工程。

### 4.3 技术栈

- **V1（薄镜像）**：Docker 多阶段 / `FROM docmost/docmost:0.96.0` 叠加品牌资产，**不需要 Node 构建**
- **V2（源码二开）**：Nx + pnpm 11.25 monorepo（`apps/client` React、`apps/server` NestJS），Node 26 构建
- **部署**：Docker Compose → macmini；nginx 反代（**必须支持 WebSocket**）
- **脚本**：一律 Python 3（遵循工作空间规范，不写 `.ps1`/`.sh`）
- **镜像仓库**：NyaaDockerHUB 私有仓库，地址只从 `.env` 的 `PRIVATE_DOCKER_REGISTRY_HOST` 注入

## 五、部署目标

| 项 | 取值 | 状态 |
|---|---|---|
| 部署机 | macmini（SSH 别名，Ubuntu 24.04 x86_64） | 已确认 |
| 项目目录 | `/root/DockerContainer/NyaaDoc/` | 按工作空间规范 |
| 持久化目录 | `/root/DockerContainer/DockerRes/NyaaDoc/` | 按工作空间规范 |
| 宿主机端口 | `127.0.0.1:3300` → 容器 `3000` | ✅ 实测空闲 |
| HTTPS 入口 | nginx `43083 ssl`，复用 macmini 现有 SAN 证书 | ✅ 实测空闲 |
| 证书 | macmini 现有 Let's Encrypt SAN 证书（目标域名见 `.env` 的 `APP_URL`） | 复用现有 LE 证书 |
| 数据库/Redis | 仅 compose 内部网络，不映射宿主机 | 安全默认 |

**无需自签证书**：macmini 现有 Let's Encrypt SAN 证书已覆盖目标域名并有 acme.sh 自动续期，
自签仅在内网 IP 直连等特殊场景备用。

> 🔒 **环境信息隔离**：部署域名、证书路径、内网地址、私有镜像仓库地址等**环境相关值一律不得硬编码在
> Git 跟踪文件中**，只能从 `.env` 注入，或在文档中以占位符（`<YOUR_DOMAIN>` / `<PRIVATE_REGISTRY>`）表述。

## 六、约束条件

### 6.1 许可与合规（硬约束）

1. 上游核心为 **AGPL-3.0**：本项目作为网络服务对外提供时，**必须提供修改后的完整源码**（§13）。
   在 GitHub 公开仓库托管即满足该义务。
2. `apps/client/src/ee`、`apps/server/src/ee`、`packages/ee` 属**独立企业许可**，
   **不得改动其许可声明、不得当作 AGPL 分发**；本项目不使用其功能。
3. 必须保留上游 `LICENSE` 与版权声明，并显著标注"本作品基于 Docmost 修改"（AGPL §5）。
4. 产品名与 Logo 使用自有的 NyaaDoc 品牌，**不得暗示与 Docmost 官方存在关联**。

### 6.2 安全（硬约束）

1. 公网只暴露 **nginx + 静态/反代**，应用端口仅绑定回环。
2. 不提交 `.env`、`.env.*`（除 `.env.example`）、数据库卷、真实 token/密钥。
3. 私有镜像仓库地址**禁止硬编码**在任何 Git 跟踪文件中。
4. 应用必需的 `APP_SECRET` 必须 ≥32 字符随机值，不得使用默认值。
5. **内容治理**：公开分享的页面会被任何人访问，敏感内容一律不得开启分享开关。

### 6.3 工作空间规范

- 自动化脚本用 Python；Docker 项目遵循 `rebuild.py` / `restart.py` / compose 双文件规范。
- 项目核心文件保留非注释、运行时可见的代码签名：`Nyaa be with you.`
- 每个阶段结束维护 `.docs` 交接文档。
