| 维度 | 结论 |
|---|---|
| 需求可达性 | ✅ 8 条功能需求 F1–F8 由上游 Docmost v0.96.0 原生覆盖，**无需自研内核** |
| 工作量 | ✅ 比预期小：中文化**上游已完成**、HTTPS 属部署层、仅外观改造需要动源码 |

## 二、架构分析

### 2.1 三层架构

```
┌─────────────────────────────────────────────────────────────┐
│ 品牌层（本项目 V1）                                          │
│   branding/locales/zh-CN/translation.json  ← 运行时覆盖       │
│   branding/icons/favicon-*.png             ← 运行时覆盖       │
│   Dockerfile: FROM docmost/docmost:0.96.0 + COPY              │
├─────────────────────────────────────────────────────────────┤
│ 上游基座（不修改，按 digest 锁定）                            │
│   Docmost v0.96.0（NestJS + React + Postgres + Redis）        │
├─────────────────────────────────────────────────────────────┤
│ 发行层（本项目 V1）                                          │
│   docker-compose.yml / .publish.yml / .env / rebuild.py       │
│   restart.py / nginx vhost / 部署文档                         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 品牌化的实现机制（**本方案的技术核心**）

实测证据链：

| 证据 | 结论 |
|---|---|
| `apps/client/src/i18n.ts` 使用 `i18next-http-backend`，未覆盖 `loadPath` | 翻译走 HTTP 运行时加载，默认路径 `/locales/{{lng}}/{{ns}}.json` |
| `GET https://demo.docmost.com/locales/zh-CN/translation.json` → 200 且返回完整中文 JSON | **运行时路径确认**，且 `zh-CN` 语言包已存在 |
| 官方 Dockerfile 将 `apps/client/dist` 整体拷入运行镜像 | 静态资源位于 `/app/apps/client/dist/`，可被 bind mount / COPY 覆盖 |
| 环境变量清单中**无**自定义 CSS / 品牌注入项 | 外观改造无法靠配置完成，必须走源码（V2） |

**推论**：**中文文案与 Logo 的替换不需要编译**——只需在薄镜像中覆盖两个目录。
这把 V1 的工作量从"fork + 构建前端"降为"写 3 行 Dockerfile"。

### 2.3 部署拓扑

```
Internet ──(路由器 TCP 转发:43083)──> macmini nginx:43083 (TLS, 现有 LE 证书)
                                        │
                                        └─ proxy_pass ─> 127.0.0.1:3300   [仅回环绑定]
                                                            │
                                                    ┌───────┴────────┐
                                                    │ NyaaDoc 容器    │
                                                    │  (Docmost)      │
                                                    └───┬────────┬───┘
                                                内部网络 │        │
                                              postgres:18  redis:8
                                              (不映射宿主机端口)
```

WebSocket 必需：实时编辑器与协作依赖 WS，nginx 需 `Upgrade`/`Connection` 头透传
（macmini 已有 `00-websocket-map.conf` 可参考）。

## 三、技术选型

### 3.1 上游选型对比（候选均于 2026-09-08 实测活跃）

| 项目 | ⭐ | 许可 | 单篇发布开关 | 编辑登录 | 结论 |
|---|---|---|---|---|---|
| **Docmost** | 21.6k | AGPL-3.0 | ✅ 页面级 Share | 本地账号/OIDC | ✅ **选定** |
| Outline | 40.5k | BSL 1.1 | ✅ | **强制 OIDC/SMTP** | ❌ 许可与登录门槛 |
| TriliumNext | 37.8k | AGPL-3.0 | ✅ | ✅ | 🟡 备选（UX 偏笔记） |
| BookStack | 19.0k | MIT | ⚠️ 角色级 | ✅ | 🟡 备选（UX 偏传统 wiki） |
| Wiki.js | 28.9k | AGPL-3.0 | ⚠️ 页面规则 | ✅ | ❌ v3 长期重写 |
| SiYuan | 46.2k | AGPL-3.0 | ✅ 只读发布 | ✅ | ❌ 发布仅只读 + 部分功能付费 |
| SilverBullet | 6.0k | MIT | ❌ 发布插件已废弃 | ✅ | ❌ 发布能力缺失 |

Docmost 胜出理由：唯一同时满足「语雀级 Web UX + 单篇发布开关 + 本地账号登录 + AGPL + 高活跃」。

### 3.2 品牌化路径选择

| 方案 | 不编译可改 | 上游升级成本 | 适用 |
|---|---|---|---|
| **A. 薄镜像覆盖静态资源（V1 选定）** | 文案 ✅ / Logo ✅ | 近零（改 tag） | V1 全部需求 |
| B. 源码 fork 改造（V2） | 组件/样式全量 | 中（merge 冲突） | 深度外观改造 |
| C. nginx 注入 CSS | 仅轻量样式 | 低 | 不推荐（维护性差、易失效） |

**选定 A 作为 V1**：以最小代价验证全链路，把源码改造的风险推迟到需求明确之后。

### 3.3 部署选型

| 项 | 选定 | 理由 |
|---|---|---|
| 容器镜像来源 | 私有 NyaaDockerHUB | 工作空间统一规范，跨机可接续 |
| 应用端口 | 宿主机 `127.0.0.1:3300` | ✅ 实测空闲；仅回环，不直接暴露 |
| HTTPS 入口 | nginx `43083 ssl` | ✅ 实测空闲（原 grep 命中的 43083 仅为注释文字） |
| 证书 | 复用现有 LE SAN 证书 | 已有自动续期链路（acme.sh），无需自签 |
| 数据库备份 | 定期 `pg_dump` | 知识库为**唯一数据资产**，必须可恢复 |

## 五、风险识别

| 编号 | 风险 | 等级 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | **AGPL 合规疏漏** | 🔴 高 | 法律风险 | 保留 LICENSE、显著标注修改、公开源码；EE 目录原样不动 |
| R2 | **公网暴露动态应用** | 🔴 高 | 被扫描/爆破/漏洞利用 | 仅回环绑定、nginx 限流、强密码、及时跟进上游安全更新、关注 CVE |
| R3 | **敏感内容误公开** | 🔴 高 | 隐私泄露 | 默认私有；分享前人工复核；建立"可公开内容清单" |
| R4 | 上游升级致覆盖失效 | 🟡 中 | 品牌化回退为 Docmost 原貌 | P5 增加**品牌化冒烟验证脚本**；升级后必跑 |
| R5 | 静态资源路径变更 | 🟡 中 | 覆盖层失效（COPY 路径不存在） | 构建期校验文件存在性，缺失即构建失败 |
| R6 | EE 许可误用 | 🟡 中 | 合规风险 | 不启用 EE 功能、不改 EE 文件、发行说明声明 |
| R7 | macmini 资源占用 | 🟢 低 | 影响其他服务 | 预估 1.2–1.5 GB 内存；现有 11 GB 可用，充裕 |
| R8 | 数据库单点 | 🟡 中 | 数据丢失 | D10 定期 dump + 持久化目录独立于容器 |
